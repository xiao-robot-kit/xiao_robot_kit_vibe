# 配方：踩坑集（多代理工作流实战坑泛化版）

> 一句话：本项目错误池的泛化沉淀——每条按「现象 → 根因 → 修复 → 预防」四段提炼成动作句；多代理工作流里，**同一类坑第二次出现就是流程违规**，所以每条都该回写进下一波的任务卡。

- **模式名**：Lessons Pool（踩坑集 / ERR 池泛化）
- **用法**：开新波前先扫一眼本表；任务卡公共纪律引用相关条目；犯新坑按四段法入池（本项目原始池：4 条原始错误，全部蒸馏为可执行规则并回写任务卡，同型错误零复发）。

## L1 相对路径赌 cwd（工作流验证门假红）

- **现象**：工作流确定性门报 `No such file or directory`，但目标文件实存；同一错误模式还被复制进第二个工作流（批量放大）。更隐蔽的复发：给运行中工作流传相对 path 修订，新 run 的 cwd = 修订那一刻的会话 cwd，**不继承原 run workspace**——修复「加目录前缀」赌错 cwd 继续假红，而被测单测本身 107 断言全绿。
- **根因**：工作流脚本的命令参数按**启动时 cwd** 解析相对路径；而主会话因日常 Bash 操作 cwd 早已漂移（多仓并行尤甚）。相对路径赌的是「cwd 恰好没变」，赌输即门假失败。
- **修复**：门里编译源/输出/可执行文件全部改**绝对路径**；对运行中工作流的任何修订参数一律绝对路径。
- **预防**：① 工作流内 `run(命令, 参数)` 的路径参数**全部绝对路径**，无例外；② 开工作流前确认会话 cwd 在预期根；③ 多仓并行会话里任何相对路径自问一句「**相对谁**」。

## L2 仿真一键脚本双宏必传（单宏致零帧挂死）

- **现象**：固件一键仿真终验各段全通（编译/镜像/起仿真/socket 连接），但 30 秒**零帧**，固件在仿真器里无任何输出。
- **根因**：一键脚本只传了「串口出口」宏，漏传「合成数据源」宏——固件进了仿真器还在等真 I2C 总线挂死，连重试日志都出不来。两个宏**正交**：管数据源的、管帧出口的，缺一即断链。
- **修复**：编译命令固定双宏齐传（数据源宏 + 串口出口宏）。
- **预防**：仿真一键脚本的编译命令**双宏一起传**写死进模板；凡「换了环境跑不起来但本地正常」，先查环境切换宏是否齐。

## L3 抄 CMake 骨架先核 cache 默认值

- **现象**：同型工程 A 的一键脚本套到工程 B 上即触发 L2（漏宏挂死）。
- **根因**：A 骨架用 `if(NOT DEFINED VAR)`（未传时默认开），B 骨架用 `set(VAR 0 CACHE STRING ...)`（**显式默认关**）——两种写法语义相反，各工程默认值可能不一致；抄骨架时想当然认为默认值相同。
- **修复**：一键脚本不赌默认值（见 L2 双宏必传）；新工程统一「未定义默认开」写法。
- **预防**：从既有工程抄骨架建新工程时，**逐个核对每个 option/cache 变量的默认值语义**（`NOT DEFINED` 默认 ≠ `CACHE` 默认）；核对结论写进任务卡。

## L4 Git Bash 调 cmd：`//c` 而非 `/c`

- **现象**：`cmd /c "长命令串"` 静默不执行（只打印 cmd 横幅即退出）——首选链路无报错地失败。
- **根因**：Git Bash（MSYS）把 `/c` 当 POSIX 路径转换成 `C` 盘根路径，cmd 收到非法参数进交互模式即退，整串命令静默不执行。
- **修复**：写 `cmd //c "..."`（双斜杠防转换）或设 `MSYS_NO_PATHCONV=1`。
- **预防**：Git Bash 里链 Windows 工具链（cmd 批处理、IDE 环境脚本）一律 `//c`；姊妹坑是 MSYSTEM 检测（MSYS 环境下 cmd 内 `set MSYSTEM=` 清除）——两招都要记。

## L5 push 的成功语义只覆盖 origin

- **现象**：从临时克隆（`git clone <本地路径>`）推远端分支，`git push` 全部 exit 0，远端却看不到分支——一度误报「已推送」。
- **根因**：本地路径克隆出的仓，其 `origin` 就是那个**本地路径**；exit 0 只证明写进了本机 .git。验证时又用了被 cut/awk 加工的输出，掩盖了「分支缺失」。
- **修复**：显式 `git push https://<远端>/<org>/<repo>.git <分支>`；推完 `git ls-remote <远端URL> <分支>` 直连复核哈希并记录。
- **预防**：凡「已推送远端」的完成态断言，以 `ls-remote` 直连证据为准，**不信任 push exit 0**，不加工验证输出。

## L6 长驻进程必限时必杀（39 分钟卡死教训）

- **现象**：仿真器类常驻进程（QEMU 等）在前台裸跑，命令永不返回，整个子代理/工作流卡死数十分钟。
- **根因**：仿真器不会自己退出；任何「裸等输出」的命令都在赌它恰好在超时前结束。
- **修复**：一律后台起进程（独立任务/`start`），限时（30~60 秒）收集输出后**必杀**（按精确 PID 或镜像名 `taskkill /F`）。
- **预防**：任务卡写死进程铁律——每条命令带 timeout；常驻进程「后台起 + 限时收 + 必杀」三步走，绝不让任何命令裸等。

## L7 写源码用编辑工具，不用 shell 重定向

- **现象**：`echo ... > file.c` 式写源码被安全钩子拦截，或绕过后内容不可审计。
- **根因**：shell 重定向绕过了文件编辑工具的审计与冲突检测层。
- **修复/预防**：写/改文件一律用编辑工具（Write/Edit）；二进制产物（编译出的 `.exe` 等）验证完即删、不入库。

## L8 已确认的墙要写进任务卡（防重复撞墙）

- **现象**：两个并行任务各自独立撞同一堵环境墙（如「仿真器对某串口通道无出口」），各花一轮排查。
- **根因**：实测得出的环境边界只留在上一个会话的报告里，新任务卡不携带。
- **修复**：墙结论以「**已确认的墙（勿再撞）**+ 解法」格式写进后续每张任务卡（例：帧输出改走仿真器有出口的通道）。
- **预防**：凡实测撞出的环境边界，立即沉淀并注入后续任务卡与 README「实测边界」段；报告里的墙是资产，不是噪音。

## 坑的沉淀仪式（四段法 + 回写）

1. **记录**：现象 → 根因 → 修复 → 预防（预防必须是「下次遇到 X 必须做 Y」的动作句，禁「以后注意」类空话）。
2. **蒸馏**：提炼成跨任务可复用的动作句（本表形态）。
3. **回写**：至少回写一处——任务卡公共纪律、门禁清单或计划文件；**只修坑不回写 = 下个会话看不到 = 等于没沉淀**。
4. **追责判据**：同类坑第二次出现且池中无对应条目 = 流程违规；子代理踩坑必须回报入池，不得私自修复了事。

实战背书：本项目 4 条原始坑全部按此仪式入池（多条曾复发一次后蒸馏），蒸馏后同型坑零复发；其中 L1 复发两轮（含批量复制进第二工作流）后，全树门参数改绝对路径，一晚 13 个完成波次再无假红门。
