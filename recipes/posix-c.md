# 配方：POSIX C 接口检查表

> 一句话：一套从实战任务卡里提炼的 C 接口纪律清单——每个新接口设计完、每次 code review 判「接口合格」之前，逐条打勾；它同时是移植重构时的目标接口形态（旧码的静态注册制/全局态是重构对象，不是基准）。

- **模式名**：POSIX-style Interface Checklist（接口风格检查表）
- **用途**：① 附在 [实现波](./workflow-build.md) 任务卡公共纪律第一条；② 作 [审查波](./workflow-review.md) 的「接口差距评估」维度；③ 新接口 PR 自查。

## 检查表（逐条打勾，任一不过即返工）

- [ ] **命名**：函数与类型 `snake_case`；无匈牙利前缀、无 CamelCase 混入。
- [ ] **返回值**：`0` = 成功、`-1` = 失败；或显式错误码枚举**并注释每个码的含义**。禁裸 `int` 语义不明。
- [ ] **指针校验**：指针参数显式校验，`NULL` 一律拒绝（返回 `-1`/错误码），不静默崩溃。
- [ ] **无隐藏全局态**：模块无常驻全局可变量；一切状态住实例结构体（见下方实例化模型）。
- [ ] **单位注释**：接口注释写明**单位与方向**——如 `g / dps / °C / 秒`，并区分入参/出参。单位可疑是 `risk` 类审查发现的高发区。
- [ ] **实例化模型**：`create/destroy` + 不透明句柄；**一个实例 = 一个对象**（一电机、一定时器、一传感器），实例数量由调用方决定，库内零静态槽位。
- [ ] **嵌套 = 句柄引用**：对象间组合用句柄字段（如电机配置持定时器句柄）——同定时器分通道、跨定时器均可，不用全局 ID 表。
- [ ] **资源对称**：`destroy` 真释放（句柄、寄存器、通道），防「只增不减」型泄漏——旧码里 destroy 不释放是典型审查雷，需配防回归测试。
- [ ] **参数零写死**：可调参数走配置结构体 + 预设表（`xxx_cfg_presets`）；代码内禁 magic number。容量/上限等 create 时传入。
- [ ] **平台件走后端抽象**：硬件依赖（I2C/flash/定时器）收敛为函数指针表后端，核心库可裸跑单测（RAM 后端内置，真硬件后端由平台适配层注册）。
- [ ] **编译标准**：`gcc -std=c99 -Wall -Wextra` **零警告**才准入门。
- [ ] **零第三方**：核心库无第三方依赖；自研 CRC/解析/算法。

## 实例化语义示例（电机库风格）

```c
/* 每电机一实例：句柄 + 配置结构体（pthread 风格） */
motor_t *m = motor_create(&(motor_cfg_t){
    .kind       = MOTOR_KIND_ENC_CLOSED,   /* 类型走枚举表 */
    .timer      = tim,                     /* 嵌套=句柄引用，非全局 ID */
    .pid        = { .kp = 2.0f, .ki = 0.2f }, /* 参数入配置，零写死 */
    .pole_pairs = 7,
});
if (m == NULL) return -1;                  /* 指针/配置校验，NULL 拒绝 */
int rc = motor_poll(m);                    /* 0=成功 -1=失败 */
motor_destroy(m);                          /* 真释放，防只增不减 */
```

## 实战数据背书（本项目真实运行）

- 电机库以此模型从零重写（旧静态注册制为重构对象）：实例化 + 注册挂载共 **1022 断言**全绿；定时器句柄嵌套（同定时器分通道 / 跨定时器）**119 断言**全绿，其中 destroy 真释放有防「旧仓只增不减」雷的回归用例；PID（含抗饱和方向断言）**78 断言**。
- 传感器组件链同纪律落地：姿态 **107 断言**、标定 **2372 断言**、持久化组件 **153 断言**——全部 gcc `-std=c99 -Wall -Wextra` 零警告编译进确定性门实跑。
- 审查波按本表做「POSIX 差距评估」写进各域移植建议，成为移植波重写接口的显式基准（两次审查 59 条发现 0 条 violation，接口差距评估独立于判据四分类单列）。

## 变体与边界

- **Python/JS 侧的同构纪律**：参数校验抛显式异常、无全局态、构造配置不写死——检查表精神跨语言成立（本项目上位机侧即按此执行）。
- 单位注释的扩展：帧协议 payload 布局（字节序、字段单位、长度）写进协议头注释——「注释写单位」对二进制协议同样适用。
- 边界：本表管**接口形态**，不管算法正确性（那是单测断言的事）；也不替代内存/并发专项审查（列 `risk` 判据交审查波）。
