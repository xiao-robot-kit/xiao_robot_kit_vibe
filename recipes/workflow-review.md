# 配方：代码审查工作流（域并行审查 + 逐条独立复核）

> 一句话：把「一份大体量存量代码能不能信、能不能移植」这个问题，交给多代理流水线——按域并行只读审查，**每条发现再派一个独立复核员重读文件求证**，只输出带证据链、经复核的发现清单。

- **模式名**：Review Fan-out with Per-finding Independent Confirmation（域并行审查 + 逐条独立复核）
- **配套配方**：审查雷产出后直接注入 [实现波](./workflow-build.md) 任务卡；接口基准可对照 [POSIX C 检查表](./posix-c.md)；过程中的踩坑见 [踩坑集](./lessons.md)

## 适用场景

- **移植/重构前的摸底**：接手一份 AI 生成或久未维护的代码，先要证据再动手，禁止「看着能跑就直接搬」。
- **AI 产出的可信度审计**：单代理审查会幻觉；用「审查员 + 复核员」双岗把幻觉率压下来。
- **要可审计证据链的合规场景**：每条发现必须落在 `文件:行号` 并附亲读原文，报告可直接作为决策依据。
- 反例（不适合）：小范围 lint（直接跑工具更便宜）、需要修复代码的审查（本配方**只读不改**，修是下一波的事）。

## 四类判据（每条发现必须归入一类）

| kind | 名称 | 判定标准 |
| --- | --- | --- |
| `fake` | 假代码 | 注释/文档/README 声称的行为与实现不符；调用不存在的函数；参数含义注释与实际使用不符（幻觉注释）。**判定门槛：注释与实现「确实不符」才算**——风格偏好不算问题 |
| `dead` | 死代码 | 不可达分支；导出但从未被调用的函数；无信息量的注释掉的代码块 |
| `violation` | 违规 | 疑似拷贝自开源项目（异常版权头、外部项目命名、风格突变）；硬编码凭据/密钥；违反原创纪律的痕迹 |
| `risk` | 风险 | 未处理的失败路径；竞态；单位/量纲可疑（注释单位与运算不符）。**按域扩展**：电机域追加 PID 积分饱和与限幅缺失、PWM 定时器/通道读-改-写竞态、编码器计数溢出/方向、S 梯度分段边界 |

严重级别三档：`low`=提示级 / `medium`=移植时需处理 / `high`=不处理会产出**错误的移植决策**。

## 结构骨架（伪代码）

```ts
// —— 数据契约（强类型输出，禁自由文本）——
interface ReviewFinding {
  where: string;     // "文件路径:行号"，如 src/core/attitude/mahony.c:42
  kind: "fake" | "dead" | "violation" | "risk";
  problem: string;   // 一句话：什么问题（不是怎么修）
  evidence: string;  // 亲读到的代码/注释行原文（截取关键行）
  severity: "low" | "medium" | "high";
}
interface DomainReview {
  domain: string;
  findings: ReviewFinding[];  // 最多 8 条，宁缺勿滥；无真问题返回空数组
  portAdvice: string;         // 该域可否提炼移植的建议（1-2 句，含防雷点）
  coverage: string;           // 实际逐文件审了什么、跳过什么及原因
}
interface ConfirmResult { holds: boolean; note: string; }  // note 引用复核员亲读的行

phase("N 域并行只读审查，逐条独立复核");
const reviews = await Promise.all(domains.map(async (d) => {
  // 1) 域审查员：只读，产出结构化 DomainReview
  const review = await agent(`审查员·${d.name}`, {
    system: "只读纪律：不得修改任何文件；每个结论必须给出 文件:行号 与亲读原文；拿不准的不报。",
  }).ask<DomainReview>(域任务卡(d, AUDIT_RULES));

  // 2) 每条发现一个独立复核员（与审查员无信息共享）
  const kept = review.findings.slice(0, 8);   // 硬上限
  const confirms = await Promise.all(kept.map((f, i) =>
    agent(`复核员·${d.key}${i + 1}`, {
      system: "独立复核：只凭给定 finding 与文件本身求证。复核不了如实说 holds=false，不要迎合。",
    }).ask<ConfirmResult>(`独立复核这条发现是否成立（读文件求证）：${JSON.stringify(f)}`)
  ));

  // 3) 复核结论并回填状态
  return kept.map((f, i) => ({
    ...f,
    status: confirms[i]?.holds ? "verified" : "unconfirmed",
    confirmNote: confirms[i]?.note ?? "（复核未执行）",
  }));
}));

phase("汇总产出审查报告");
// 总表（位置/类别/级别/状态/问题）+ 分域详情 + 移植建议 + 复核说明 + 未覆盖声明
await artifact.markdown("audit-report", 汇总(reviews));
```

## 关键纪律（缺一条配方就失效）

1. **审查员与复核员分离**：复核员只拿到 finding 本身和文件路径，不拿到审查员的推理过程——独立性是降噪的全部来源。
2. **复核不迎合**：复核员 system prompt 明写「复核不了如实说 holds=false」。`unconfirmed` 不是丢弃，是**保留并标注**，不作为阻塞依据，留人工判断。
3. **宁缺勿滥 + 每域硬上限 8 条**：上限逼审查员排序，只报高信号发现；上限同时控制复核员的 fan-out 成本（发现数 × 1 个复核员）。
4. **coverage 必填**：审了什么、跳过什么、为什么跳——没有覆盖声明的审查报告不可信。
5. **notCovered 显式声明**：静态审查不覆盖实机运行行为、git 历史考古、叙述性文档全文——在结论里写明，防止「审查过=没问题」的过度推断。
6. **只读铁律**：审查波零写操作，因此可与任何实现波并行（文件域零冲突），这是审查波常驻并行位的原因。

## 汇总报告结构

- 头部一行结论：`N 条发现，其中 M 条复核成立`（两个数字必须来自真实结果计算）。
- 总表：`位置 | 类别 | 级别 | 状态 | 问题`；空发现也显式写「无发现」。
- 分域详情：portAdvice + coverage + 每条 finding 的「证据：亲读原文」与「复核：复核员引用的行」。
- 复核说明图例：`✅ 成立` vs `⚠️ 未复核成立` 的语义边界。

## 实战数据背书（本项目两次真实运行）

| 审查波 | 域数 | 亲读文件 | 发现 | 复核成立 | fake | dead | risk | violation |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 传感器（IMU）侧 | 4 | 37 文件 + 3 目录 | 25 条 | **25 条（100%）** | 11 | 6 | 8 | **0** |
| 电机侧 | 5 | 23 文件 + 1 目录 | 34 条 | **34 条（100%）** | 10 | 4 | 20 | **0** |

- 电机侧 `risk` 占比最高（20/34），其中 **4 条 high**（编码器竞态 ×2、哨兵值域、换频失准）——全部在后续移植波任务卡里以「审查雷（必修）」逐条处理并加防回归测试。
- `violation=0` 不是走过场：判据里明确列了版权头/外部命名/硬编码凭据的扫描点，发现为零即如实报零。
- 复核员产出直接改变了输出质量：所有 `fake` 判定都经「注释与实现确实不符」的复核门槛，风格偏好被挡在门外。

## 变体与边界

- **域特有判据扩展**：`risk` 是开放类，按被审域追加（协议域加帧长度校验、持久化域加原子性/断电语义）。
- **POSIX 差距评估**：要求每域审查员顺带评估「与目标接口规范（snake_case / 0=-1 / 实例化无全局态）的差距」写进 portAdvice，为重写接口的下一波提供基准。
- 成本模型：域审查员 N 个 + 复核员 Σ findings 个；上限 8 条/域把最坏情况钉在 N + 8N。
- 已知边界：静态审查不验证运行行为与时序；发现为空 ≠ 代码正确，只等于「未报出有证据的问题」。
