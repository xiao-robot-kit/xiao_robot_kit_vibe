# 配方：实现波（任务卡驱动 + 确定性验证门 + 一轮修复）

> 一句话：把一批实现/移植任务按**文件域拆成并行波**，每张任务卡自带公共纪律与验证命令；波尾不采信子代理的口头汇报，而是由脚本**实跑编译+单测拿退出码**当确定性门，失败给**一轮**修复机会后如实记录红绿。

- **模式名**：Task-card Build Wave with Deterministic Gates（域拆分实现波 + 确定性门）
- **上游**：审查波的雷清单（见 [代码审查工作流](./workflow-review.md)）注入本波任务卡；接口纪律用 [POSIX C 检查表](./posix-c.md)；坑提前读 [踩坑集](./lessons.md)

## 适用场景

- 多模块并行实现或移植（组件库、固件 app、上位机三线同跑）。
- 子代理自报「已完成」不可全信——需要**机器可判定**的验收（编译 exit 0 + 单测 exit 0），而不是读它的总结。
- 长任务挂机推进（配 [心跳自动驾驶](./heartbeat-autopilot.md) 按波接力）。

## 结构骨架（伪代码）

```ts
// —— 任务卡产出契约：issues 不许写「无」——
interface TaskResult {
  task: string;          // 与派发一致的任务名
  filesWritten: string[];// 写入/修改的文件清单
  verification: string;  // 验证命令与实际输出摘要（未跑就写未跑+原因）
  issues: string;        // 遇到的问题、未完成项（没有写"无"）
}

// —— 公共纪律块：逐卡拼接，不依赖子代理记忆 ——
const COMMON_RULES = [
  "1. 接口规范（snake_case / 0=成功 -1=失败 / 指针显式校验 / 无全局可变态 / 注释写单位与方向）",
  "2. 原创律：禁第三方库、禁网络拷贝；允许提炼自有旧码（引用行号重组，不照搬失实注释）",
  "3. 参数零写死：可调参数走结构体/预设表，代码内禁 magic number",
  "4. 写文件一律用编辑工具（Write/Edit）；测试产物编译后删除不入库",
  "5. 环境事实（编译器/警告级/路径含空格）",
  "6. 实事求是：验证输出必须真实执行所得；做不到写进 issues，禁止虚报完成",
].join("\n");

phase("第一波并行：按文件域互斥拆分");
const wave1 = await Promise.all([
  agent("测试工程师·组件A").ask<TaskResult>(任务卡A + COMMON_RULES),
  agent("移植工程师·组件B").ask<TaskResult>(任务卡B + COMMON_RULES),  // 含审查雷清单
  agent("纪律编辑·文档").ask<TaskResult>(任务卡C + COMMON_RULES),
]);

phase("第二波：挂接第一波产出（依赖波）");
const wave2 = await Promise.all([
  agent("固件工程师·app2").ask<TaskResult>(前置读 wave1 头文件 + 任务卡 + COMMON_RULES),
  agent("固件工程师·app4").ask<TaskResult>(前置读 wave1 头文件 + 任务卡 + COMMON_RULES),
]);

phase("确定性验证门：脚本实跑，不问子代理");
const gateResults = [];
for (const gate of gates) {  // 每门 = 编译 + 运行，退出码是唯一判据
  let { exit, output } = await world.run(gcc, [编译参数..., 绝对路径], { timeoutMs: 120_000 });
  if (exit === 0) ({ exit, output } = await world.run(测试exe, [], { timeoutMs: 60_000 }));
  let fixed = false;
  if (exit !== 0) {                      // 失败 → 一轮修复（不无限循环）
    await agent("修复员·" + gate.name).ask("测试门失败，读源码只修必要处（守公共纪律）：\n" + output);
    ({ exit, output } = await 重跑(gate));
    fixed = true;
  }
  gateResults.push({ name: gate.name, exit, output, fixed });
}

phase("汇总实现报告");
// 门表（退出码/修复轮/输出尾）+ 每任务 filesWritten/verification/issues
const gateOk = gateResults.every((r) => r.exit === 0);
await artifact.markdown("build-report", 汇总(gateResults, [...wave1, ...wave2]));
```

## 关键纪律

1. **确定性门 = 脚本实跑退出码**：`world.run` 直接执行编译与测试命令（每条带 timeout）；门的红绿不来自任何代理的叙述。编译门与运行门分离——编译过 ≠ 测试过。
2. **失败修复只给一轮**：失败 → 修复员（带失败输出尾）→ 重跑 → 记录 `fixed`。二轮仍红就如实进报告（`存在未通过的门`），交给主会话/人工——不无限自动重试掩盖问题。
3. **公共纪律逐卡拼接**：纪律写在任务卡文本里而不是 system 提示一处——每张卡自包含，子代理拿卡即拿全部约束。
4. **文件域互斥拆分**：并行任务的写入集合两两不相交是第一波可并行的前提；实在要共享契约文件时，任务卡写明协调规则——
   - 接口约定先行：「另一并行任务正在写 X——你按上述接口约定引用；文件尚不存在时编列即可，**不要自己另写一份（避免双源）**」；
   - 共享头文件：「若被并行任务改动过，先 Read 最新版再改，**Edit 只追加不覆盖**」。
5. **任务卡四件套**：被测/依赖代码（先读）→ 产出清单（含路径）→ 验证命令（写死命令行，子代理必须真实跑）→ 遗留如实写。审查雷以「【high/medium】必修 + 修法」的格式逐条注入。
6. **环境事实与已确认的墙写进卡里**：已实测的环境结论（如「仿真器某串口通道无出口，帧输出改走 UART0」）作为「已确认的墙（勿再撞）」注入，防止并行任务重复撞同一堵墙。
7. **门参数一律绝对路径**（见 [踩坑集 L1](./lessons.md)）：会话 cwd 会被漂移，相对路径赌启动时 cwd 不变，赌输即门假红。

## 汇总报告结构

- 头部一行：`确定性验证门全绿` 或 `存在未通过的门`（由 exit 码计算）。
- 门表：`门 | 退出码 | 修复轮（—/经一轮修复） | 输出尾`——输出尾带真实日志片段。
- 任务产出：每任务 `文件 / 验证 / 遗留` 三行；`issues` 原文保留（包括「需人工开窗口确认」类）。
- notCovered：写明哪些验证没做（实机、窗口视觉、IDF 级编译成败见各任务 issues 等）。

## 实战数据背书（本项目真实运行）

- **传感器移植波**（六任务两波 + 三门）：门全绿——姿态组件单测 **107 断言**、标定组件 **2372 断言**（当时口径；该组件现已扩至 3,402 断言）、上位机模拟流 **300 帧 0 丢帧**。审查雷（重复标定不清累加器等）修毕并有防回归用例。
- **电机实现波**（四门）：全绿——定时器句柄嵌套 **119 断言**、PID **78 断言**、电机实例化 **1022 断言**、S 梯度全相位断言。
- **验收波**（只读盘点 + 全套总跑）：功能矩阵 61 项（实测 37 / 仅编译 1 / 部分 21 / 缺失 2），测试套 **7/7 绿**——缺口如实转任务清单，不粉饰 partial。
- 长跑连续性：14.4 小时内 13 个完成波次接力（审查 → 移植 → 验收 → 实验矩阵 → 补齐），门红绿全程由脚本判定（含 9 次被替换重开的运行——重开原因如实入 [踩坑集](./lessons.md)）。

## 变体与边界

- **单工程师长链**：小波不必 fan-out——单代理做完「算法+页面+测试」整链，门在尾部件兜底（本项目 3D 轨迹实验即此形态：算法单测门 + 页面交付）。
- **门分级**：gcc/python 实跑列确定性门；`idf.py build` 这类环境依赖编译**不列门**（子代理尝试，成败如实进 issues）——确定性门必须是你自己能稳定复跑的命令。
- 并行度约束：写域互斥优先于速度；不能互斥就改成波次依赖（wave2 等 wave1）。
- 边界：门验证的是「单测断言全过」，不覆盖页面视觉、实机硬件行为——这些必须显式进 notCovered 留人工。
