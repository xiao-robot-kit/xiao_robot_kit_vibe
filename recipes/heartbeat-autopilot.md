# 配方：心跳自动驾驶（定时勘察：有活不打断、顺手收口、空闲开新波）

> 一句话：用宿主的定时注入（cron）每 10 分钟向主会话投一条**幂等勘察指令**——运行中有活就只做顺手收口（阶段提交），全部空闲就按计划文件开下一波工作流，让「跑一晚上都搞不完」的大活清单在无人值守下持续推进。

- **模式名**：Heartbeat Autopilot（心跳勘察自动驾驶）
- **配套配方**：开出去的每一波都按 [实现波](./workflow-build.md) 组织、审查按 [审查波](./workflow-review.md)；坑见 [踩坑集](./lessons.md)

## 适用场景

- **挂机长跑**：任务清单远超单轮会话容量（「估计你要跑一晚上都搞不完」），用户要求「保证你一直在工作」。
- **多波次接力**：波与波之间有先后依赖（审查 → 移植 → 验收 → 实验矩阵），但单个人盯不过来。
- 不适合：一次性小任务（心跳是空转成本）、强人工决策节点的任务（等用户拍板的事不该自动开波）。

## 结构骨架

```
宿主 cron（每 10 分钟）──注入──▶ 主会话收到「心跳勘察」prompt
                                     │
                ┌────────────────────┼────────────────────┐
                ▼                    ▼                    ▼
        ① 查运行状态          ② 有进行中的？          ③ 全部空闲？
        （工作流运行列表）          │                      │
                                不打断                  读计划文件按序
                                顺手阶段提交：            开下一波工作流
                                git status → 分仓          （多子代理 +
                                commit + push，            携带公共纪律 +
                                只 add 明确路径            前波报告/雷清单）
                                （避开正在写的文件）        │
                └────────────────────┴────────────────────┘
                                     ▼
                    ④ 三行内简报：进行中 / 本轮提交 / 下一步
```

### 心跳 prompt 模板（脱敏骨架，可直接套用）

```text
心跳勘察（守护任务线持续推进）：按序执行——
1) 查看本项目工作流运行状态，确认是否有 running/pending 的工作流；
2) 若有进行中的：不打断。检查各仓未提交的阶段成果（git status），
   有已完成的可验证成果就分仓 commit + push（凭据走密钥服务/环境变量，
   命令行即时拼装；只 add 明确路径，避开工作流正在写的文件）；
3) 若全部空闲：读 <计划文件> 的任务线，推动下一阶段——
   大活开多子代理工作流（域拆分 + 复核员 + 确定性门），
   接口守规范、参数零写死、写文件用编辑工具；
   前波报告的缺口/雷清单先读再动手；
4) 用三行内简短汇报当前状态（进行中 / 本轮提交 / 下一步）。

铁律：禁止创建任何新的心跳或调度任务；不要打断进行中的工作流；
同一文件域避免与运行中工作流并行写。
```

### 计划文件里的「心跳指引」段（接力协议）

计划文件（todo 类）除了任务清单，末尾挂一段给心跳读的接力协议，例：

```text
### 心跳指引（上一波完成后按此接力）
1. 上一波完成通知 → 收口提交（分仓）+ 勾掉对应任务项
2. 报告出 → 读缺口清单 → 登记为下一波补充项
3. 空闲时按清单顺序逐个开实验波（单波单实验，文件域独立，完成即提交）
4. 全部完成 → 汇总总战报等用户
```

## 关键纪律（铁律清单）

1. **禁自繁殖**：心跳内禁止创建任何新的心跳/调度任务——否则指数级自复制。
2. **禁打断**：有 running/pending 工作流时心跳只做只读勘察 + 顺手提交，绝不干预运行中的波。
3. **文件域防冲突**：顺手提交只 `add` 明确完成的路径，不 `add -A`——工作流可能正在写别的文件。
4. **幂等短勘察**：单次心跳只做轻量动作（查状态、提交、开波、三行简报），不做长操作——宿主通知机制不区分忙碌，长心跳会在忙时制造干扰。
5. **状态的单一事实源**：全部推进状态住计划文件一处，心跳只读写它；不靠会话记忆续跑。
6. **简报三行封顶**：每次心跳的输出是「进行中 / 本轮提交 / 下一步」——防心跳刷屏淹没真正的用户消息。
7. **凭据纪律**：顺手提交需要远端凭据时从密钥服务/环境变量读，token 值绝不落进任何文件与日志（输出一律掩码）。

## 实战数据背书（本项目真实运行）

- **68 次心跳注入，跨 14.4 小时挂机**，期间驱动 25 个工作流运行（13 个完成波次完成接力：两轮代码审查 → 移植重构 → 仿真链路 → 验收矩阵 → 压轴联调 → 四个实验波 → 补齐波 → 开源化），其余 9 次为按坑修正后被替换重开的运行、3 次为收尾时仍在跑的波。
- 接力全程零打断事故：进行中的波从未被心跳干预；阶段成果按「分仓 + 明确路径」逐波上云，一晚结束时各仓 dev 分支与本地进度一致。
- 心跳期间出现的坑（相对路径门假红、仿真进程卡死）按 [踩坑集](./lessons.md) 沉淀并在后续波任务卡注入，同型错误未再复发。

## 变体与边界

- **周期选择**：10 分钟适配「波粒度 20 分钟~数小时」的节奏；波更细则缩到 5 分钟，更粗可放宽（过密=空转，过疏=空闲窗口浪费）。
- **忙时静默（宿主级增强）**：若宿主可感知「会话有子任务在途」，可把心跳的完成通知改为忙时静默投递、空闲才唤醒（需改宿主通知链路；判定时必须排除心跳自身，否则心跳永远看到自己在跑 → 永不唤醒）。不改宿主时，靠铁律 4（幂等短勘察）达到同等效果。
- **开波前置检查**：开新波前先确认「前波报告已出且已读」——依赖未就绪就开波会把错误批量放大。
- 边界：心跳推动的是**已规划好**的任务线；发现新需求/方向性问题应登记回计划文件等用户，不自行加戏。
